Webhook Handlers (from Stripe)

POST /v1/webhooks/stripe

Handle Stripe events for subscription lifecycle

// Handled Events:
- customer.subscription.created    → Create subscription record
- customer.subscription.updated    → Update plan/status
- customer.subscription.deleted    → Mark as canceled
- invoice.paid                     → Record payment, reset usage
- invoice.payment_failed           → Mark as PAST_DUE
- customer.subscription.trial_will_end → Send reminder email

What Gets Metered

Metric Description Billing Impact
Input Tokens Tokens sent to LLM (prompts, context) Counted toward usage limits
Output Tokens Tokens generated by LLM (responses) 5x weight vs input tokens
Cache Read Tokens Tokens served from prompt cache 10% of normal token cost
API Requests Number of API calls made Rate limiting per tier
Model Type Which LLM model was used Different pricing per model

📝 Summary

The Kiro platform is a large-scale AI developer tool serving 250K+ weekly active users. My work focuses on the Subscription and Usage Metering layer, which:

  • Tracks 140M+ weekly API requests across all user tiers
  • Manages 80K+ paid subscriptions with Stripe integration
  • Supports complex billing scenarios (tiered plans, usage-based overage, enterprise invoicing)
  • Enables fraud detection at scale (700K+ suspicious accounts identified)
  • Provides real-time usage data for cost optimization (contributed to 72% cost reduction)
